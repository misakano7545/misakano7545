# 通用规则

我名下仓库的通用约定。本文件是规则源，放在 `agent-docs/` 下不会被 agent 自动加载；要用时拷到目标仓库根目录并改名 `AGENTS.md`。

```bash
gh api repos/misakano7545/misakano7545/contents/agent-docs/common-agent.md --jq .content | base64 -d > AGENTS.md
```

`AGENTS.md` 只在仓库根目录（cwd）生效，agent 工具不会向上找，所以放子目录没用。各仓库可以另写自己的 `AGENTS.md` 补充，仓库本地的为准。

## 提交信息

- type 前缀带英文小写，标题用中文：`docs: 新增资产登记流程初版`。
- 分隔符是半角 `:` 加一个空格。
- 句末不加句号。
- 不加 footer（`Co-Authored-By`、`BREAKING CHANGE`）。
- 有实质改动就写正文，一条一个 `- `；纯改错别字可省。
- 要追溯就标来源：`（同步上游 #92 · 5e0adb3）`。

## 命名

- 目录名、文件名一律中文，不加英文别名（不要 `asset-资产登记.md`）。
- 例外只有两个，工具认死的名字：`README.md`（GitHub 只认它渲染仓库首页）、`AGENTS.md`（agent 工具只认这个名字）。
- **会上传或被服务端解析的文件名用 ASCII**：平台上传的图片、要拼进 URL 的产物、给外部系统读的文件。目录名用中文没有代价，因为不上传。

## 中文写作

- 引用章节写「第 N 节」，如「见第 5.2 节」。不用西文节号符。
- 界面或字段名套「」：`运行日志下新增「积分历史」`。

## 结构

- **一个事实只有一个源。** 草稿区、暂存区不算权威源；不要复制权威源的文件当草稿。
- 不为还不存在的东西先造脚手架（CI、模板、脚本、空目录）：等真的重复了再加。
- 反馈写在文件自己的变更记录里，不另开 issue 台账。
